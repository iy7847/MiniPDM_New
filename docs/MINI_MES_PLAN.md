# [Phase 4] Mini MES (수주/생산/출하) 기획 및 아키텍처 설계서

이 문서는 소규모 임가공 업체의 현실적인 현장 흐름(작업자 중심 동적 라우팅)을 반영한 **MiniPDM v2.0 생산관리 모듈**의 최종 설계서입니다. 
영업에서 이관된 수주를 바탕으로 생산, 공정, 외주/구매 관리를 효율적으로 통제하는 것을 목표로 합니다.

## 1. UI 메뉴 구조 및 역할 (사이드바 - 생산관리 그룹)
기존의 복잡한 BOM 등록이나 공정(Routing) 사전 설계 과정을 과감히 생략하고, 수주 리스트가 곧 BOM이 되며 작업자가 공정을 직접 리드하는 '유연한' 구조를 채택합니다.

### 1) 생산 관리 (Production Management)
*영업에서 넘어온 수주를 생산 준비 상태로 세팅하는 관리자/공무용 화면*
* **선행 단계 (영업 수주 관리)**: 영업팀에서 수주 이관 시 도면과 함께 라벨(바코드)을 출력하여 도면에 부착한 상태로 생산팀에 전달.
* **수주 이관 접수**: 라벨이 부착된 도면을 인계받고, 생산 관리 화면에서 대기 중인 수주 품목(`order_items`) 리스트 확인.
* **생산 계획 확정**: 
  * 납품 수량과 별도로 불량/재고용 여유 수량 변경 가능.
  * 조달 방식 분리 및 지정 (`supply_type`: 사내가공 / 외주 / 기성품 구매).
  * **재고 사용 여부 결정**: 원소재 재고뿐만 아니라, 이전에 가공해 둔 **완제품 재고**의 사용 여부도 함께 결정 가능하도록 처리.
  * 신규 가공이 필요한 경우에만 소재 발주 리스트로 이관.

### 2) 공정 관리 (Process Management / Shop Floor)
*현장 작업자가 직접 바코드를 찍으며 작업 실적을 기록하는 현장용 키오스크/태블릿 화면*
* **작업자 직접 공정 설계 (동적 라우팅)**:
  * 도면 바코드 스캔 시 해당 품목 상세 정보 팝업.
  * **시작**: 현재 본인이 작업할 공정(예: 선반, MCT)을 직접 선택하고 `[시작]` 버튼 클릭. (`process_logs` start_time 기록)
  * **종료**: 작업 완료 후 수량(양품/불량) 입력. 그 후 `[다음 공정으로 넘김]`, `[중간 외주로 넘김]`, `[최종 완료]` 중 하나를 선택하여 종료. (`process_logs` end_time 기록)
* **중간 외주 처리**: 가공 중 외주가 필요하면 외주처 선택 후 완료 처리 (외주 대기 상태로 전환).
* **불량 및 재작업(Rework) 처리 정책 (수량 분할 및 파생 오더 생성)**:
  * 가공 중 불량 발생 시 사유 입력 및 사진 첨부.
  * 정상품은 다음 공정으로 그대로 흘러가며, **불량 난 수량만큼 시스템이 새로운 하위 오더(예: 기존품번-R1)를 파생 생성(Split)**합니다.
  * 쪼개진 파생 오더용 새로운 바코드를 출력하여 처음(소재 발주) 또는 이전 공정부터 재작업을 시작합니다. (바코드 기반 현장 추적성을 극대화하기 위한 최적의 방식)
* **출하 검사**: 별도의 검사 메뉴 없이, 현장 작업의 마지막 단계(공정명: '출하 검사')로 검사자가 바코드를 스캔하여 검사 진행 및 출하 확정.

### 3) 외주/구매 관리 (Outsource & Purchase Management)
*소재 발주 및 중간 가공 외주를 통합하여 발주하고 입고를 잡는 화면*
* **외주/구매 통합**:
  * 소재 구매 (`material_orders`)
  * 중간 공정 외주 (`outsource_orders` - 열처리, 후처리 등)
  * 기성품 구매 (완제품)
* **발주 진행 및 스마트 메일 전송**: 
  * 공급사(외주처/구매처) 선택 후 발주서(PO) PDF 생성.
  * **[메일 전송]**: 앱 내에 설정된 대표 메일(네이버, 지메일 한정) 프리셋을 통해 공급사에게 발주 메일 자동 발송.
  * **수신 확인(Read Receipt) 트래킹**: 메일 본문에 '발주서 보기' 전용 링크를 포함하여 전송하며, 외주처에서 해당 링크를 클릭해 발주서를 열람하면 DB에 자동으로 **[수신 확인 완료]** 상태와 열람 시간이 기록되는 트래킹 프로세스 적용.
* **입고 처리**: 물건이 도착하면 시스템상에 입고(`received_date`) 처리하여 다음 공정(현장)으로 다시 투입될 수 있도록 상태 업데이트.

## 2. DB 스키마 매핑 설계
현재 확립된 DB 스키마를 바탕으로 위 기획안을 완벽하게 수용합니다.

* **`order_items`**: 생산 관리 리스트의 근간. `supply_type`(조달), `use_stock`(재고 사용), `qty`(실제 생산수량), `client_po_no`(고객사 발주번호) 컬럼 활용. 
  * 파생 오더(Rework) 발생 시 신규 행(Row) 생성.
* **`process_logs`**: 공정 관리 현장 실적. `process_name`(공정명), `worker`(작업자), `start_time`, `end_time`, `status`, `notes`(불량 사유 등) 활용.
* **`material_orders`**: 원소재 묶음 구매 관리.
* **`outsource_orders`**: 중간 공정(열처리 등) 및 완제품 외주 발주 관리.

## 3. 기술 구현 가이드라인 (Technical Implementation Details)

### 3.1. 프론트엔드 핵심 로직 (React Hooks & UI)
* **`useBarcodeScanner` (바코드 감지 훅)**: (✅ 구현 완료)
  * 한글 오타 역변환 (IME Issue) 보정 로직 구현.
  * 포커스 스틸 방어(preventDefault) 구현.
* **`useStickySearchParams` (필터 복원 훅 고도화)**: (✅ 구현 완료)
  * 리스트 화면의 필터 Clear 상태 및 뒤로가기 상태 완벽 복원.
* **UI 컴포넌트 신규 개발**: (✅ 구현 완료)
  * 현장 태블릿 화면을 위한 `KioskLayout`, `KioskLargeButton`, `MESStatusBadge`, `ImageUploader` 등 구축 완료.

### 3.2. 데이터베이스 및 백엔드 전략 (Supabase)
* **바코드(채번) 하이브리드(Base33) 룰 적용**: (✅ 구현 완료)
  * 수주 확정 시 `P{YYMM}-{XXX}-{YY}` 규칙에 따라 DB 단에서 `order_item_no` 자동 채번.
* **재작업 파생 오더 분할 RPC (`split_rework_order`)**: (✅ 구현 완료)
  * 불량 발생 시 `order_items` 제약 조건 충돌 없이 `-R1` 꼬리표를 붙여 신규 채번 후 분할 INSERT 하는 트랜잭션.
* **무인증 메일 수신 확인 Edge Function (`po-read-receipt`)**: (✅ 구현 완료)
  * 외주 업체가 메일 속 링크를 클릭하면 `SERVICE_ROLE_KEY`로 RLS를 우회하여 수신 확인 처리 완료.

## 4. [중요] 향후 잔여 작업 및 마이그레이션 과제 (Current Status & Next Steps)

현재 생산 관리(`ProductionListPage`)의 기반 작업(컬럼 추가, 재고 사용 로직, 채번 등)은 완료되었으나, 이와 강하게 결합되어야 하는 **공정 관리(현장)**와 **외주/구매 관리**는 아직 기존 구조에 머물러 있거나 껍데기만 존재하는 상태입니다. 다음 작업을 통해 시스템을 100% 연동해야 합니다.

### 4.1. 생산 관리 ↔ 외주/구매 관리 데이터 연동 (단절 해결)
* **문제점**: 현재 생산 관리 화면에서 `[선택 항목 진행]`을 눌러 `OUTSOURCE_READY`나 `PURCHASE_READY`로 상태를 넘겨도, 실제 `outsource_orders`나 `material_orders` 테이블에 데이터가 Insert 되지 않아 외주/구매 관리 화면에 데이터가 뜨지 않는 단절 상태입니다.
* **해결 과제**:
  * `transferToOutsourceOrPurchase` 액션 실행 시, 조달 방식(`supply_type`)이 `OUTSOURCE`이거나 소재 조달(`material_supply_type`)이 `ORDER`인 경우, 백엔드 RPC나 프론트엔드 로직을 통해 **실제 `outsource_orders` 및 `material_orders` 테이블에 초기 레코드를 생성(Insert)**하는 로직을 추가해야 합니다.
  * 실제 메일 발송 로직(Resend 등 연동)이 포함된 `send_po_email` Edge Function을 추가 개발하여 Dummy Alert를 대체해야 합니다.

### 4.2. 공정 관리(Shop Floor)의 완벽한 생산관리(Base33) 기반 개편
* **문제점**: 채번 룰은 Base33으로 바뀌어 스캔은 되지만, 현장 키오스크 화면(`ShopFloorPage`)의 내부 State Machine과 공정 이동 로직이 새롭게 추가된 `supply_type`이나 `production_qty`를 온전히 반영하여 처리하고 있지 않습니다.
* **해결 과제**:
  * 공정 시작/종료 시 중간 외주(Outsource)가 발생할 경우, 단순히 `process_logs`에만 남기는 것이 아니라 즉시 `outsource_orders`로 데이터가 생성(분기)되도록 로직을 결합해야 합니다.
  * 출하 검사 완료 시 재고 테이블(완제품 재고) 수량을 업데이트하는 기능 등 생산관리의 확장된 개념을 현장 화면에 모두 반영해야 합니다.
