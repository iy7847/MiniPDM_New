```

소재비:   중량 × kg당단가
가공비:   가공시간 × 시간당임률 × 난이도계수
열처리비: 중량 × 열처리 kg당단가
후처리비: 중량 × 후처리 kg당단가

중량(사각): (가로 × 세로 × 두께 × 비중) / 1,000,000
중량(원형): (π × 반지름² × 길이 × 비중) / 1,000,000
```

## 💾 데이터 목록 화면 설계 원칙 (필수)

### 1. URL 기반 상태 동기화 및 상태 유지 (Sticky Filters)
모든 데이터 목록(List) 페이지(수주, 생산, 출하, 자재 등)를 개발할 때는 다음 원칙을 **무조건** 따릅니다.
- 검색어, 필터(기간, 상태 등), 페이지네이션 번호는 단순 `useState`로 관리하지 않고 **반드시 브라우저의 URL Query Parameter(`?search=...&page=...`)에 동기화**해야 합니다.
- **Sticky Filters 적용**: 사용자가 대시보드나 다른 메뉴에 갔다가 사이드 메뉴를 통해 다시 해당 목록 페이지로 진입(`URL이 파라미터 없이 깔끔한 상태`)하더라도, 이전에 검색했던 필터와 페이지가 그대로 복원되어야 합니다. 이를 위해 `sessionStorage`를 활용하여 URL Parameter를 저장하고 복원(Re-hydrate)하는 로직을 필수적으로 구현합니다. 
- **[중요] Race Condition 방지**: React Router의 특성상 페이지를 벗어날 때(unmount 직전) `useSearchParams`가 비어있는 상태로 재렌더링되며 기존 `sessionStorage`를 초기화해버리는 버그가 발생할 수 있습니다. 이를 방지하기 위해 `sessionStorage.setItem`을 호출할 때는 **반드시 현재 주소(`location.pathname`)가 해당 목록 페이지의 주소와 일치할 때만 저장**하도록 Guard(방어 로직)를 추가하세요.
- **[중요] 검색창 Debounce 충돌 방지**: URL 파라미터가 외부(세션 복원, 뒤로가기 등)에 의해 변경되었을 때, 지연 검색(Debounce) 로직용 내부 상태값(`localSearch`)이 동기화되지 않으면 빈 값으로 덮어쓰는 버그가 발생합니다. 반드시 `useEffect(() => { setLocalSearch(search); }, [search]);`를 추가하여 URL 변경 시 로컬 검색어 상태를 즉시 동기화하세요.
- **목적**: 상세 페이지에 들어갔다가 '뒤로가기'를 누를 때뿐만 아니라, 다른 작업을 하다가 다시 해당 메뉴를 클릭해 진입했을 때도 사용자의 작업 컨텍스트가 100% 유지되도록 하여 최고의 UX를 제공하기 위함입니다.
- **구현**: `react-router-dom`의 `useSearchParams`와 `useLocation` 및 브라우저 내장 `sessionStorage`를 결합하여 커스텀 훅(`use[Feature]List`) 내에서 처리하세요.

### 2. 서버 사이드 페이징 및 필터링 (Server-Side Pagination & Filtering)
- 모든 리스트 페이지는 전체 데이터를 한 번에 조회(Fetch All)하지 않습니다. 브라우저 과부하 방지를 위해 반드시 **Supabase 쿼리 단에서 페이징(`.range()`)과 검색 필터링(`.ilike()`)**을 수행하고 결과만 가져오도록 설계합니다.
- 데이터 로딩 시 검색어 입력에 의한 과도한 API 호출을 막기 위해 디바운스(Debouncing)를 적용합니다.
